# Project structure

```text
.
├── index.html               single page that loads everything (English)
├── es/index.html            same page for the Spanish site
├── assets/
│   ├── css/theme.css        theme (colors are variables)
│   ├── js/app.js            Markdown reader, menu, search
│   ├── img/                 favicon and social image
│   └── vendor/              marked and highlight.js (bundled)
├── docs/                    ← your documentation lives here
│   ├── config.json          name, language, repository…
│   ├── nav.json             menu (generated, do not edit)
│   ├── index.md             home page
│   └── …folders with .md files
├── docs-es/                 Spanish version of the documentation
├── tools/
│   ├── build-nav.mjs        generates each nav.json
│   ├── build-site.mjs       assembles the site into _site/
│   └── serve.mjs            development server
└── tests/                   tests for the tooling
```

## What you touch every day

The `docs/` folder. The rest (`index.html`, `assets/`, `tools/`) only changes if you want to alter behavior or design. If your site has a single language, you can delete `docs-es/` and `es/`.

## What each file in `docs/` does

| File | Purpose |
| ---- | ------- |
| `config.json` | Site name, language, repository link… See [Configuration](../customize/01-configuration.md). |
| `nav.json` | Sidebar menu. Generated by `tools/build-nav.mjs`; it gets overwritten. |
| `index.md` | The home page. It does not appear in the menu or in search. |
| `*/_meta.json` | Optional: title and order of a folder. |

> [!NOTE]
> Files and folders whose name starts with `_` or `.` are ignored when the menu is generated. Use that for drafts.
